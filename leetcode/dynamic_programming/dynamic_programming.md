# 动态规划

## 一、DP通用解法四步骤

所有动态规划题目遵循 **固定四步求解流程** ，核心顺序不可颠倒： **确定DP数组含义 → 确定递推公式 → 确定初始化 → 确定遍历顺序** ，所有DP题型均基于该流程演变。

### 1. 确定DP数组的含义

dp[i] 或 dp[i][j] 代表什么。

核心问题：是"前i个"还是"第i个"？开多大的数组？一维还是二维？

**为什么要开 n+1？** 因为要返回 `dp[n]`，下标从 0 到 n，一共 n+1 个位置。开 n 的话只能到 `dp[n-1]`，不够用。

### 2. 确定递推公式

dp[i] 如何由前面的子问题推出，即**状态转移方程**。

### 3. 确定如何初始化

dp 数组的初始值（边界条件），即递推公式的起点。

### 4. 确定遍历顺序

按什么顺序填表：从前往后还是从后往前？维度间怎么遍历？

> **关键：确定遍历顺序之前必须先确定初始化，否则无法填表。**

## 二、DP本质：从子问题推导当前问题

和回溯的本质对比：

| | 回溯 | 动态规划 |
|---|---|---|
| **本质** | 递归模拟 n 层 for 循环 | 从子问题推导当前问题 |
| **方向** | 深度优先，一路走到黑再回头 | 填表，从小问题开始逐步推大问题 |
| **核心操作** | 做选择 → 递归 → 撤销选择 | 填 dp 表，dp[i] 由前面的状态推出 |

## 三、背包问题的两种子题型（极其重要）

同样是背包问题，**求最大价值**和**求方案数**的递推公式完全不同：

| | 求最大价值 | 求方案数 |
|---|---|---|
| **问题** | 装满容量为 j 的背包，最多能装多少？ | 装满容量为 j 的背包，有多少种方法？ |
| **递推公式** | `dp[j] = max(dp[j], dp[j-w[i]] + v[i])` | `dp[j] += dp[j - w[i]]` |
| **初始化** | 全 0（什么都没选，价值为 0） | `dp[0] = 1`，其余为 0（凑出 0 有一种方案：什么都不选） |
| **为什么** | 选或不选，取**较大值** → 用 `max` | 选或不选都能到达，方案数**相加** → 用 `+=` |
| **典型题目** | 416、1049、carl46 | 494（目标和） |

**适用范围**：这个区分在 0/1 背包和完全背包中都成立，区别只在于内层循环方向（倒序 vs 正序）。

**一句话记忆**：取最大用 `max`，数方案用 `+=`。

## 四、核心题型分类

### 题型一：斐波那契型（递推只依赖前几个状态）

**特征**：dp[i] 只依赖前面常数个状态，递推公式是固定模式。

```cpp
// 爬楼梯、斐波那契
dp[i] = dp[i-1] + dp[i-2]

// 最小花费爬楼梯（746）
dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])
// 初始化：dp[0] = dp[1] = 0（题目说可以从第0或第1阶开始，免费）

// 整数拆分（343）
dp[i] = max(j*(i-j), j*dp[i-j], dp[i])
// j*(i-j): 拆成两个数（i-j 不拆）
// j*dp[i-j]: 拆成两个以上（i-j 继续拆）
// dp[i]: 之前 j 循环积累的最大值

// 递推公式的本质：对每个 j，比较 (i-j) 到底拆不拆？
// 循环范围：j 从 2 到 i-2（不访问 dp[1]，避免未定义 + 对称性去重）
```

**典型题目**：509、70、746、343

---

### 题型二：二维网格路径（只能向右或向下）

**特征**：二维 dp 数组，每个格子只能从上方或左方转移过来。

```cpp
dp[i][j] = dp[i-1][j] + dp[i][j-1]  // 无障碍
// 有障碍时，障碍格 dp[i][j] = 0
```

**初始化**：第一行和第一列只能从一个方向到达（全 1 或根据障碍设置）。

**62 vs 63 对比：**

| | 62（无障碍） | 63（有障碍） |
|---|---|---|
| **dp 初始化** | 全开 0，第一行/列设为 1 | 全开 0，第一行/列设为 1（遇到障碍停止） |
| **递推执行条件** | 无条件执行 | 只在 `obstacleGrid[i][j]==0` 时执行 |
| **起点/终点检查** | 不需要 | 起点或终点是障碍直接 return 0 |
| **返回值** | `dp[m][n]`（开 m+1 数组） | `dp[m-1][n-1]`（开 m×n 数组） |

**63 题关键点：**
- 初始化第一行/列时，遇到障碍必须 **break**，后面所有格子保持 0（被挡住了，不可能到达）
- 递推时障碍格不处理，保持原始值 0

**典型题目**：62（不同路径）、63（不同路径II，加障碍）

---

### 题型三：卡特兰数（二叉搜索树计数）

**特征**：以每个节点为根，左右子树独立，结果 = 左子树数量 × 右子树数量，遍历所有根节点求和。

**递推公式**：
```cpp
dp[i] += dp[j-1] * dp[i-j]
// j 从 1 到 i，j 是根节点
// dp[j-1]: 左子树有 j-1 个元素
// dp[i-j]: 右子树有 i-j 个元素
```

**初始化**：`dp[0] = 1`（空树是一种合法的 BST，也是递推公式能运行的必要条件）

**为什么 dp[0] = 1？** 当 j=1 时（1 做根），左子树 0 个元素，结果是 `dp[0] * dp[i-1]`。如果 dp[0]=0，这个根的贡献就是 0，整个结果就错了。

**典型题目**：96（不同的二叉搜索树）

### 题型四：0/1 背包（每个物品只能用一次）

**核心问题**：给定容量和物品，每个物品只能选一次。递推公式见第三章（求最大价值 vs 求方案数）。

#### 二维写法（理解用）

**dp 含义**：`dp[i][j]` = 背包容量为 j，从物品 0~i 中选，最大价值。

**递推公式**：
```cpp
dp[i][j] = max(dp[i-1][j], dp[i-1][j - weight[i]] + value[i])
//             不选第i个        选第i个
```

**初始化**：
```cpp
// dp[i][0] = 0（容量为0，装不了任何东西）
// dp[0][j]：只有物品0，容量j时的价值
for (int j = weight[0]; j <= W; j++)
    dp[0][j] = value[0];
```

**遍历顺序**：先物品还是先背包都可以。因为 `dp[i][j]` 依赖的是正上方 `dp[i-1][j]` 和左上方 `dp[i-1][j-weight[i]]`，不管先遍历哪个方向，这两个位置都已经计算好了。

#### 一维空间优化（实际写法）

**dp 含义**：`dp[j]` = 背包容量为 j 时的最大价值。

**递推公式**：
```cpp
dp[j] = max(dp[j], dp[j - weight[i]] + value[i])
//        不选当前物品   选当前物品
```

**为什么 dp[j] 就是"不选当前物品"？**

因为数组复用空间，`dp[j]` 在被当前物品更新之前，存的是上一轮的结果，也就是二维的 `dp[i-1][j]`。所以不改它就是不选当前物品。

```
第 i 轮开始前：dp[j] = dp[i-1][j]（上一轮的结果）
执行 max(dp[j], dp[j-weight[i]] + value[i])
         ↑               ↑
    dp[i-1][j]     dp[i-1][j-weight[i]] + value[i]
    （不选当前物品）    （选当前物品）
```

**一维和二维的对应关系：**

| 一维 | 二维 | 含义 |
|------|------|------|
| `dp[j]`（未更新） | `dp[i-1][j]` | 不选当前物品 |
| `dp[j-weight[i]]` | `dp[i-1][j-weight[i]]` | 选当前物品 |

**为什么 1D 不需要开第二维？**

因为**倒序遍历**自动保证了这一点：计算 `dp[j]` 时，`dp[j]` 和 `dp[j-nums[i]]` 都还没被当前物品更新过，它们天然就是上一层 `dp[i-1]` 的结果。所以 1D 版本不需要显式记录 `i-1`，倒序遍历本身就是 `dp[i-1]` 的替代品。

**遍历顺序（关键）**：**必须先物品，再倒序遍历背包**

```cpp
for (int i = 0; i < n; i++)                    // 外层：物品
    for (int j = target; j >= weight[i]; j--)  // 内层：背包，倒序！
        dp[j] = max(dp[j], dp[j - weight[i]] + value[i]);
```

**为什么必须倒序遍历背包？**

```
正序遍历 j：dp[j] → dp[j-weight[i]] 已经被当前物品更新过了
             → 同一个物品被选了多次 → 这是完全背包的行为

倒序遍历 j：dp[j-weight[i]] 还是上一轮的值（没被当前物品更新）
             → 一个物品只选一次 → 这是 0/1 背包的行为
```

**为什么必须先物品再背包？（不能反过来）**

如果先遍历背包（外层 j 倒序，内层遍历所有物品）：对于每个容量 j，遍历物品 i 时 `dp[j-weight[i]]` 还没被更新（j 从大到小走，j-weight[i] < j 还没处理到），所以 `dp[j-weight[i]] = 0`。结果是**只能选一个物品**，不可能组合多个物品，不符合 0/1 背包的逻辑。

**典型题目**：carl46（背包基础）、416（分割等和子集）、1049（最后一块石头的重量II）、494（目标和）、474（一和零，二维约束）

### 题型五：完全背包（每个物品可用无限次）

#### 二维写法

**dp 含义**：`dp[i][j]` = 从物品 0~i 中选，容量为 j 的最大价值（和 0/1 背包一样）。

**递推公式**：
```cpp
dp[i][j] = max(dp[i-1][j], dp[i][j - weight[i]] + value[i])
//             不选第i个        选第i个（注意是 dp[i] 不是 dp[i-1]）
```

**和 0/1 背包的区别**：选当前物品时用 `dp[i][j-weight[i]]`（当前行）而不是 `dp[i-1][j-weight[i]]`（上一行），因为完全背包允许重复选当前物品。

**初始化**：`dp[i][0] = 0`；`dp[0][j]` 需要考虑物品 0 可以被多次选取：
```cpp
for (int j = weight[0]; j <= W; j++)
    dp[0][j] = dp[0][j - weight[0]] + value[0];  // 物品0可以重复选
```

**遍历顺序**：都可以（先物品再背包，或先背包再物品），因为正序遍历保证左边和上面都已更新。

#### 一维空间优化（实际写法）

**递推公式**：
```cpp
dp[j] = max(dp[j], dp[j - weight[i]] + value[i])
//        不选当前物品   选当前物品
```

**和 0/1 背包的唯一区别：正序遍历**。

**为什么正序？**

```
倒序（0/1 背包）：dp[j-weight[i]] 还没被更新 → 是上一层的值 → 只能选一次
正序（完全背包）：dp[j-weight[i]] 已经被当前物品更新过了 → 可以重复选
```

正序遍历时，先更新小的 j，再更新大的 j。处理 `dp[j]` 时，`dp[j-weight[i]]` 已经是当前轮更新过的值，里面已经包含了"选当前物品"的结果，所以可以继续叠加 → 一个物品被选了多次。

**遍历顺序（关键区分）**：都是正序，但**先物品还是先背包决定了是组合还是排列**。

| 遍历顺序 | 结果 | 原因 |
|---|---|---|
| **先物品，再背包** | **组合数**（顺序无关） | 物品按固定顺序出现，{1,2} 和 {2,1} 只算一次 |
| **先背包，再物品** | **排列数**（顺序有关） | 同一组物品可以按不同顺序出现，{1,2} 和 {2,1} 算两次 |

**为什么？** 画出二维 DP 表来看：
- 先物品再背包：一行一行填，物品顺序固定（1 永远在 2 前面）→ 组合
- 先背包再物品：一列一列填，后面出现的物品可以和前面的混合排列 → 排列

**编码细节**：

```cpp
// 先物品再背包：j 从 coins[i] 开始，不需要 if 判断
for (int i = 0; i < n; i++)
    for (int j = coins[i]; j <= amount; j++)

// 先背包再物品：j 从 1 开始，需要 if 判断容量是否够
for (int j = 1; j <= amount; j++)
    for (int i = 0; i < n; i++)
        if (j >= coins[i])  // 容量够才能用这个物品
```

#### leetcode 518. 零钱兑换II（完全背包求方案数，组合数）

**问题**：给定硬币数组 coins 和金额 amount，求凑出 amount 的方案数（每种硬币可用无限次）。

**四步骤**：
1. **dp 含义**：`dp[j]` = 凑出金额 j 的方案数
2. **递推公式**：`dp[j] += dp[j - coins[i]]`（不选 + 选当前硬币）
3. **初始化**：`dp[0] = 1`（凑出金额 0 有一种方案：什么都不选）
4. **遍历顺序**：**先物品，再正序遍历背包**（求组合数）

```cpp
for (int i = 0; i < n; i++)                    // 先物品
    for (int j = coins[i]; j <= amount; j++)   // 正序遍历背包
        dp[j] += dp[j - coins[i]];
```

for (int j = 1; j <= target; j++)              // 先背包
    for (int i = 0; i < n; i++)                // 再物品

#### leetcode 322. 零钱兑换（完全背包，求最小值）

和前面求方案数的区别：**求最小值，不是求方案数**。

**两个关键点**：

1. **初始化为 INT_MAX**：求最小值，一开始假设所有金额都凑不出（INT_MAX），能凑出就被更小的值更新

2. **递推公式前要判断子问题是否有解**：
```cpp
dp[j] = min(dp[j], dp[j - coins[i]] + 1);
// 但前提是 dp[j - coins[i]] != INT_MAX
// 如果 dp[j-coins[i]] 还是 INT_MAX，说明这个子问题无解
// 没必要 +1，因为无解 + 1 还是无解
```

```cpp
// 完整写法
for (int i = 0; i < n; i++)
    for (int j = coins[i]; j <= amount; j++)
        if (dp[j - coins[i]] != INT_MAX)  // 子问题有解才更新
            dp[j] = min(dp[j], dp[j - coins[i]] + 1);
```

#### leetcode 139. 单词拆分（完全背包，物品从字符串截取）

**问题**：给定字符串 s 和单词表 wordDict，判断 s 能否被拆分为 wordDict 中的单词。

**核心区别**：之前的背包题物品是给定的数组，这道题的"物品"是从字符串中**截取的子串**，需要遍历所有截取位置然后去 wordDict 里查。

**四步骤**：
1. **dp 含义**：`dp[i]` = 长度为 i 的子串 `s[0:i]` 能否被拆分
2. **递推公式**：`dp[i] = dp[j] && s[j:i] 在 wordDict 中`（j 从 0 到 i-1）
3. **初始化**：`dp[0] = true`（空串可以被拆分，也是递推能运行的起点）
4. **遍历顺序**：先遍历背包（i 从 1 到 s.length），再遍历截取位置 j

```cpp
dp[0] = true;
for (int i = 1; i <= s.length(); i++)        // 背包：字符串长度
    for (int j = 0; j < i; j++)              // 截取位置
        if (dp[j] && wordDict.count(s.substr(j, i - j)))
            dp[i] = true;
```

**和标准完全背包的对比**：

| | 标准完全背包 | 139（单词拆分） |
|---|---|---|
| **物品来源** | 给定的数组 | 从字符串截取的子串 |
| **遍历物品** | 遍历数组下标 | 遍历截取位置 j |
| **判断是否可选** | `j >= weight[i]` | `wordDict.count(s.substr(j, i-j))` |
| **本质** | 完全背包 | **完全背包（物品动态生成）** |

**典型题目**：carl52（完全背包基础）、322（零钱兑换，求最小数量）、518（零钱兑换II，求组合数）、377（组合总和IV，求排列数）

### 题型六：子集/子序列问题（转化为背包）

**特征**：从数组中选取子集满足某种条件，本质是 0/1 背包的变体。

#### 核心转化：求最大价值 → 能不能装满

当 `value[i] = weight[i]`（每个数的价值等于它的重量）时：
- `dp[j]` = 背包容量为 j 时，能装的最大价值
- 因为价值不可能超过重量，所以 `dp[target]` 最大就是 target
- **`dp[target] == target` → 背包装满了 → 找到了一个子集和为 target → 可以等分**

这就是把"求最大价值"转化为"能不能装满"的关键。

#### leetcode 416. 分割等和子集

**转化**：数组能否分成两个等和子集 → 背包容量为 sum/2，每个数的 weight = value = nums[i]，能不能装满

**四步骤：**
1. **dp 含义**：`dp[j]` = 背包容量为 j 时能装的最大价值
2. **递推公式**：`dp[j] = max(dp[j], dp[j - nums[i]] + nums[i])`（标准 0/1 背包）
3. **初始化**：全 0
4. **遍历顺序**：先物品，再倒序遍历背包

**判断条件**：`dp[target] == target` → true，否则 false

**注意**：sum 为奇数直接返回 false（不可能等分）

#### 其他类似题目

**416 vs 1049 对比（都是分成两堆）：**

| | 416（分割等和子集） | 1049（最后一块石头的重量II） |
|---|---|---|
| **问题** | 能不能等分 | 两组差最小 |
| **dp[target]** | 装满就是 target | 装了多少就是多少 |
| **判断** | `dp[target] == target` → true/false | `sum - 2 * dp[target]`（剩余的差） |
| **共同点** | 都是 0/1 背包，target = sum/2，weight = value = nums[i] |

#### leetcode 494. 目标和（求方案数，构造思路极其巧妙）

**问题**：给数组 nums 和目标值 target，每个数前面可以加 `+` 或 `-`，求有多少种方式使结果等于 target。

**构造思路（核心）**：

只研究 left 组（加号组），left 满足条件 right 自然满足：
```
left + right = sum      （所有数的总和）
left - right = target   （加号组 - 减号组 = 目标值）
→ left = (sum + target) / 2
```

**转化**：从 nums 中选若干个数，有多少种方式凑出 `left = (sum + target) / 2`？这就是 **0/1 背包求方案数**。

**前提检查**：`sum + target` 必须是偶数；`abs(target) > sum` 直接返回 0。

**四步骤**：
1. **dp 含义**：`dp[j]` = 凑出容量 j 的方案数
2. **递推公式**：`dp[j] += dp[j - nums[i]]`（不选当前物品 + 选当前物品）
3. **初始化**：`dp[0] = 1`（凑出 0 有一种方案：什么都不选）
4. **遍历顺序**：先物品（从 0 开始），再**倒序**遍历容量

**0 的处理（2^n）**：

当 `nums[i]=0` 时，`dp[j] += dp[j-0]` 即 `dp[j] += dp[j]`，方案数自动翻倍。

本质：0 放 left 组或 right 组，left 值不变，但确实是两种不同选择，所以方法数 ×2。有 n 个 0 就是 2^n。从第 0 个物品开始遍历，遇到 0 自然翻倍，不需要额外处理。

**一维中 dp[j] 的含义（极其重要）**：

`dp[j]` **永远代表 `dp[i-1][j]`**（上一轮的结果），因为外层遍历物品、内层倒序遍历容量，计算 `dp[j]` 时它还没被当前物品更新过。

```
dp[j]（未更新）  = dp[i-1][j]        → 不选当前物品
dp[j-nums[i]]    = dp[i-1][j-nums[i]] → 选当前物品
```

**典型题目**：494（目标和）

#### leetcode 474. 一和零（重量有两个维度的 0/1 背包）

**问题**：给定二进制字符串数组 strs，和整数 m（0 的上限）、n（1 的上限），找出最大子集大小，使得子集中最多有 m 个 0 和 n 个 1。

**核心理解：它还是 0/1 背包，只是"重量"有两个维度**。

`dp[i][j]` 不是二维背包，而是一维背包的重量用两个维度表示：
- `dp[i][j]` = 最多用 i 个 0 和 j 个 1，能装的最大子集大小

**四步骤**：
1. **dp 含义**：`dp[i][j]` = 最多 i 个 0、j 个 1 能装的最大子集大小
2. **递推公式**：`dp[i][j] = max(dp[i][j], dp[i - zeros][j - ones] + 1)`（标准 0/1 背包，只是减的是两个维度）
3. **初始化**：全部为 0
4. **遍历顺序**：先物品，再倒序遍历两个维度（i 从 m 到 zeros，j 从 n 到 ones）

**和标准 0/1 背包的对比**：

| | 标准 0/1 背包 | 474（一和零） |
|---|---|---|
| **重量维度** | 1 个（容量 j） | 2 个（0 的个数 i，1 的个数 j） |
| **递推** | `dp[j] = max(dp[j], dp[j-w]+v)` | `dp[i][j] = max(dp[i][j], dp[i-z][j-o]+1)` |
| **本质** | 一维背包 | **一维背包，重量有两个维度** |

**典型题目**：474（一和零）

## 五、0/1 背包 vs 完全背包：最核心的区别

| | 0/1 背包 | 完全背包 |
|---|---|---|
| **物品使用次数** | 每个物品只能用一次 | 每个物品可以用无限次 |
| **内层循环方向** | **逆序**（从大到小） | **正序**（从小到大） |
| **状态转移** | `dp[i-1][j-weight[i]]`（上一行） | `dp[i][j-weight[i]]`（当前行，允许重复选） |

**一句话记忆：逆序 = 不重复（0/1），正序 = 可重复（完全）。**

## 六、初始化规则

| 题目类型 | 初始化 | 含义 |
|----------|--------|------|
| **求最大值** | `dp[j] = 0` | 什么都没选，价值为 0 |
| **求最小值** | `dp[j] = INT_MAX` | 一开始假设无法凑出，能凑出就被更小的值更新 |
| **求方案数** | `dp[0] = 1`，其余为 0 | 凑出金额 0 有一种方案（什么都不选） |

## 七、易错点

1. **DP四步骤必须完整**：确定DP数组含义→递推公式→初始化→遍历顺序，缺一不可
2. **状态定义不清**：dp[i][j]的含义必须明确，是"前i个"还是"第i个"
3. **边界条件遗漏**：dp[0][j]和dp[i][0]需要单独处理
4. **遍历顺序错误**：bottom-up需要先计算子问题；0/1背包空间优化时需要逆序遍历
5. **混淆0/1背包和完全背包**：完全背包用dp[i][j-w[i]]而非dp[i-1][j-w[i]]
6. **数组开小了**：要返回 dp[n] 就必须开 n+1 大小，否则越界
