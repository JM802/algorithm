# 回溯算法

## 一、回溯算法固定四大核心步骤

所有回溯题目遵循 **固定闭环执行流程** ，核心顺序不可颠倒： **for循环遍历当前层 → 选择当前层元素 → 递归进入下一层 → 递归结束、撤销当前层选择（回溯）** ，所有回溯题型均基于该流程演变。

### 1. 设定递归终止条件（核心分两类题型）

终止条件的核心区别在于 **结果收集的节点位置** ，对应刷题中两大高频题型，完美区分子集类题目：

#### 题型1：叶子节点收集结果

适用场景： **限定长度的子集、固定个数的组合** 。

逻辑：只有递归走到路径的最后一个节点（叶子节点），满足指定长度/条件时，才收集当前结果。

举例：求数组中长度为2的所有子集、求k个数的组合。

#### 题型2：所有节点收集结果

适用场景： **求所有子集、所有合法子序列** （无长度限制）。

逻辑：递归过程中， **每一个节点（每一条临时路径）都是合法结果** ，每次递归进入新层级都要收集一次结果。

举例：输出一个数组的全部子集、所有非递减子序列。

### 2. for循环：遍历当前层 + 做出选择（核心关键）

for循环负责 **横向遍历当前递归层的所有可选元素** ，每一次循环就是一次**选择当前层元素**的操作，确定当前路径的节点，为下层递归做铺垫。

核心逻辑区分： **for循环管横向宽度（遍历当前所有可选、做选择），递归管纵向深度（向下探索新路径）** 。

### 3. 递归：进入下一层深度

基于当前for循环选中的元素，继续向下递归，探索更深层的所有组合可能，构建完整路径。

### 4. 回溯：递归后撤销选择

当下层所有递归探索全部完成后，执行回溯操作， **撤销当前层刚刚做出的选择** ，恢复路径初始状态，回到上一层，继续执行for循环的下一次遍历，尝试其他可选元素，遍历所有可能性，这是回溯算法能够穷举所有路径的核心。

## 二、回溯的本质：模拟 n 层 for 循环

### 1. 单集合遍历 = 用 startindex 替代嵌套 for 循环

当题目是对**单个集合**进行遍历（如从 1~n 中选 k 个数），本质就是嵌套 for 循环，但 k 是变量写不了固定层数。回溯用递归自动展开这 k 层，**startindex 标识当前模拟到第几层**。

```cpp
// 两层 for 循环
for (int i = 1; i <= n; i++)
    for (int j = i + 1; j <= n; j++)
        // ...

// 回溯等价写法：startindex 就是 i，递归展开内层
for (int i = startindex; i <= n; i++) {
    path.push_back(i);
    backtracing(n, k, i + 1);  // i+1 就是内层的 j 从哪开始
    path.pop_back();
}
```

**关键：单集合遍历不需要单独处理第一个节点**，因为 backtracking 函数内已经完整处理了所有节点的遍历。调用时只需 `backtracing(n, k, 1)` 传入起始位置即可。这和之前总结的 DFS 的套路一一致——第一个点在函数内处理。

### 2. 多集合遍历 = 用 index 控制深度，每层完整遍历

当题目是**多个独立集合各选一个元素**（如 leetcode17 每个 digit 对应一个字母集合），不能用 startindex，因为每个集合是独立的，不存在"回头"问题。每层 for 循环都从 `i = 0` 开始，遍历当前集合的完整内容。

**startindex vs index 的本质区别：**

| | 单集合（77/216） | 多集合（17） |
|---|---|---|
| **控制维度** | startindex 控制**宽度** | index 控制**深度** |
| **for 循环起点** | 从 startindex 开始，逐渐后移 | 每层都从 0 开始 |
| **含义** | `j = i + 1`，不回头选前面的 | 当前处理第几个集合 |
| **树形特征** | 宽度逐渐缩小 | 每层宽度独立不变 |

```cpp
// leetcode17: 多集合遍历
void backtracing(string digits, int index) {
    if (index == digits.size()) {   // 深度到头，收集结果
        res.push_back(path);
        return;
    }
    int mapindex = digits[index] - '0';
    string letter = lettermap[mapindex];
    for (int i = 0; i < letter.size(); i++) {  // 每层从0开始，完整遍历当前集合
        path.push_back(letter[i]);
        backtracing(digits, index + 1);         // index+1 进入下一层（下一个集合）
        path.pop_back();
    }
}
```

**分类判据：拿到一道题先问——是一个集合选多个，还是多个集合各选一个？**

### 切割问题 = 组合问题的变体

切割问题本质上就是组合问题，区别只在于"选的东西"不同：

| | 组合问题（77） | 切割问题（131） |
|---|---|---|
| **选的是什么** | 数字 | 断点位置（index） |
| **集合是什么** | {1, 2, ..., n} | {0, 1, 2, ..., len-1} |
| **startindex 代表** | 可选范围的起点（防止回头选前面的数字） | 可选范围的起点（防止回头切前面的位置） |
| **for 循环的 i 代表** | 当前选的数字 | 当前这一刀切到哪 |
| **递归传 i+1** | 下一个数字不能回头 | 下一刀从当前位置之后开始 |
| **终止条件** | path.size() == k | startindex >= s.size() |
| **收集的是什么** | 选中的数字列表 | 切出的子串列表 |

```
组合问题: 从 {1,2,3,4,5} 选 2 个
  选 1 → 从 {2,3,4,5} 选 1 个
  选 2 → 从 {3,4,5} 选 1 个
  ...

切割问题: 字符串 "aab"，从 {0,1,2} 选切割点
  切到 0（切出 "a"）→ 从 {1,2} 继续切
  切到 1（切出 "aa"）→ 从 {2} 继续切
  切到 2（切出 "aab"）→ 结束
```

**一句话：切割问题就是把字符串下标当作集合，选切割点就是选数字。**

### 3. 剪枝：每道题不同，核心思想一致

剪枝的本质是**提前排除不可能的分支**，具体条件因题而异：

| 题目        | 剪枝条件                         | 含义                                     |
| ----------- | -------------------------------- | ---------------------------------------- |
| leetcode77  | `i <= n - (k - path.size()) + 1` | 剩余可选数不够 k 个，提前结束            |
| leetcode216 | `sum > n` + 同上                 | 和已经超了，不用继续；剩余不够也不用继续 |
| leetcode39  | 排序 + `sum + candidates[i] <= target` | 和超过 target 直接跳过，因为排序后后面更大 |
| leetcode40  | 排序+同层去重                    | 有数量限制+不能重复使用                  |

### 3.5 sum 类题目剪枝：排序 + for 循环条件剪枝

leetcode39 这类**求和型回溯**，关键优化是**先排序再剪枝**：

```cpp
sort(candidates.begin(), candidates.end());  // 先排序
for (int i = startindex; i < candidates.size() && sum + candidates[i] <= target; i++)
```

排序后 `sum + candidates[i] > target`，说明当前元素已经超了，后面更大的元素更不可能，**直接跳出整个 for 循环**，效率远高于在函数入口 `if (sum > target) return`（那个只跳过当次递归，for 循环还会继续）。

### 3.6 元素可重复选：startindex 不 +1

77/216 每个元素只能选一次，递归传 `i + 1`；leetcode39 同一个元素可以重复选，递归传 `i`：

```cpp
// 不能重复选（77/216）
backtracing(..., i + 1);  // 下一层从 i+1 开始，不包含当前元素

// 可重复选（39）
backtracing(..., i);      // 下一层从 i 开始，还能再选当前元素
```

### 3. 是否需要显式回溯：看有没有改掉原变量

核心原则：**只要原变量被改了（不管是值传递的副本还是引用传递的原变量），就需要手动恢复。**

```cpp
// 写法一：sum += i（无论值传递还是引用传递，sum 都被改了，必须手动回溯）
void backtracing(int n, int k, int sum, int startindex) {
    sum += i;                    // sum 被改了（即使是值传递的副本）
    backtracing(n, k, sum, i+1);
    sum -= i;                    // 必须手动恢复
}

// 写法二：创建新变量，原 sum 没被动过，不需要回溯
void backtracing(int n, int k, int sum, int startindex) {
    int new_sum = sum + i;       // 原 sum 没被改
    backtracing(n, k, new_sum, i+1);
    // 不需要 sum -= i
}

// 写法三：直接传表达式，等价于写法二，不需要回溯
void backtracing(int n, int k, int sum, int startindex) {
    backtracing(n, k, sum + i, i+1);  // sum 没被改
}
```

**写法二和写法三本质一样**：原 sum 没有被修改，不需要回溯。写法一 `sum += i` 直接改了 sum，不管值传递还是引用传递，都必须 `sum -= i` 恢复。

## 三、回溯高频难点：去重问题（刷题核心）

### 1. 什么情况下需要去重？

| 情况 | 是否去重 | 原因 |
|------|----------|------|
| 集合无重复元素（77/216/17） | 不需要 | startindex 本身就能保证不重复选取 |
| 集合有重复元素 + 每个元素只能选一次（40） | **需要** | 排序后相邻相同值会导致同层重复 |
| 集合有重复元素 + 元素可重复选（39） | 不需要 | 元素可重复选，不存在"同层重复"问题 |
| 求所有子集/排列且有重复元素（90） | **需要** | 同理，同层不能选相同值 |

**判据：集合本身有重复元素 + 每个元素只能用一次 → 需要去重。**

### 2. 去重的两个概念：树层去重 vs 树枝去重

```
        [1, 1, 2, 3]  排序后
           1
         / | \
       1*  2  3       ← 树枝：同一个1被选两次（不同层）→ 允许
      /|\
     1  2  3          ← 树层：同层又选了1 → 不允许
```

- **树枝去重（允许）**：不同层级选相同值，是不同元素（下标不同），在同一条路径上可以共存。比如路径 [1, 1, 2]，第一个1和第二个1虽然值相同，但它们是数组中不同位置的元素，这是合法的。
- **树层去重（必须禁止）**：同一层 for 循环中，已经选过值为1的元素了，再选一个值为1的就会产生重复结果。比如同一层选第一个1得到 [1,...]，再选第二个1也得到 [1,...]，结果一模一样。

### 3. 去重的前提：必须先排序

排序是为了让**相同值的元素相邻**，这样才能在 for 循环中通过 `candidates[i] == candidates[i-1]` 发现重复。不排序的话，相同值散落在各处，无法用相邻比较去重。

### 4. 去重的实现：used 数组

```cpp
sort(candidates.begin(), candidates.end());
vector<bool> used(candidates.size(), false);

for (int i = startindex; i < candidates.size(); i++) {
    // 树层去重：同层跳过相同值
    if (i > 0 && candidates[i] == candidates[i-1] && used[i-1] == false)
        continue;

    used[i] = true;
    path.push_back(candidates[i]);
    backtracing(target, sum + candidates[i], candidates, i + 1, used);
    used[i] = false;
    path.pop_back();
}
```

**`used[i-1] == false` 的含义：前一个相同值的元素已经回溯了（不在当前路径中），说明当前层已经试过这个值了，跳过。**

**`used[i-1] == true` 的含义：前一个相同值的元素还在路径中（还没回溯），说明是不同层的递归，允许选。**

### 5. 典型对应题目

力扣 40. Combination Sum II：集合有重复元素，每个元素只能选一次，必须树层去重。
