# 贪心算法

## 一、贪心算法的本质

贪心算法的核心是**每一步都做出当前看起来最优的选择**，尝试用局部最优推导全局最优。

**关键区别：贪心 vs 动态规划**

- **贪心**：不能严格证明一定是全局最优。只能先设计一个贪心策略，尝试后验证结果是否正确。适用于题目本身具有贪心性质的情况（如排序后局部最优就是全局最优）。
- **动态规划**：可以严格推导出全局最优解，通过状态转移方程枚举所有子问题。

### leetcode 455. 分发饼干

**题目**：每个小孩有一个胃口值 g[i]，每块饼干有一个大小 s[j]。一块饼干最多只能满足一个小孩，求最多能满足几个小孩。

**贪心策略**：大饼干优先满足大胃口的小孩。

**为什么这样贪心？**

- 排序后，胃口大的小孩最挑剔，大饼干都满足不了他，小饼干更不可能
- 所以从大胃口的小孩开始处理，用当前最大的饼干去尝试满足
- 如果能满足，就用掉这块饼干（index--），小孩数量 +1
- 如果满足不了，说明当前饼干太小，换下一个更大的饼干（但已经是最大的了，所以这个小孩就放弃）

**遍历顺序**：两个数组都排序，从后往前遍历（从大到小）

**双指针移动规则**：


| 指针    | 表示什么                             | 什么时候移动                                                      |
| ------- | ------------------------------------ | ----------------------------------------------------------------- |
| `i`     | 当前要考虑的小孩，从大胃口往小胃口走 | 每轮都移动，因为这个小孩要么被满足，要么只能放弃                  |
| `index` | 当前还没使用的最大饼干               | 只有满足`s[index] >= g[i]` 时才移动，因为只有这时饼干才真正被用掉 |

**本质**：孩子可以被放弃，所以孩子指针每轮都往前；饼干是资源，只有成功匹配时才消耗。

**代码：**

```cpp
sort(g.begin(), g.end());
sort(s.begin(), s.end());

int index = s.size() - 1;  // 饼干从最大的开始
int result = 0;

for (int i = g.size() - 1; i >= 0; i--) {  // 小孩从胃口最大的开始
    if (index >= 0 && s[index] >= g[i]) {
        index--;    // 用掉这块饼干
        result++;   // 满足一个小孩
    }
    // 不满足就跳过这个小孩（大饼干都满足不了，小饼干更不行）
}
```

**一句话记忆**：大饼干配大胃口；如果最大饼干都满足不了当前孩子，这个孩子就只能放弃，饼干不能浪费。

### leetcode 376. 摆动序列

这道题可以用 DP，也可以用贪心。DP 更像是在枚举所有可能的结尾状态；贪心则是直接抓波峰和波谷。

#### 方法一：DP

**核心状态**：

- `up[i]`：强制以 `nums[i]` 结尾，并且最后一步是上升的最长摆动子序列长度
- `down[i]`：强制以 `nums[i]` 结尾，并且最后一步是下降的最长摆动子序列长度

**为什么每个位置要同时保存 up 和 down？**

因为同一个 `nums[i]` 既可能作为一个“上升结尾”，也可能作为一个“下降结尾”。后面再接新数字时，这两种身份都有可能变成最优答案。


| 做法                                      | 问题                                             |
| ----------------------------------------- | ------------------------------------------------ |
| 只用一个`flag` 标记当前位置是上升还是下降 | 默认一个位置只能保留一种选择，会把另一种可能丢掉 |
| 同时保留`up[i]` 和 `down[i]`              | 不提前丢状态，后面需要上升或下降时都能接         |

**递推公式**：

```cpp
if (nums[i] > nums[j])
    up[i] = max(up[i], down[j] + 1);
else if (nums[i] < nums[j])
    down[i] = max(down[i], up[j] + 1);
```

**为什么这样转移？**

- 当前是上升：前一步必须是下降，所以用 `down[j] + 1`
- 当前是下降：前一步必须是上升，所以用 `up[j] + 1`

**和 LIS 的共同点**：这类子序列 DP 都要定义成“强制以某个数结尾”，因为只有知道结尾数字，才能判断后面能不能接。

**返回值细节**：

通用写法是遍历时用 `result` 记录 `max(up[i], down[i])`，最稳。

#### 方法二：贪心

**贪心策略**：只保留方向发生改变的位置，也就是波峰和波谷。

连续上升的一段，中间点都不重要，只要保留最高点；连续下降的一段，中间点也不重要，只要保留最低点。这样局部保留转折点，就能得到最长摆动序列。

**为什么要处理平坡？**

如果有连续相同数字，差值为 0，会干扰“正负号变化”的判断。可以先用 `unique` 去掉连续重复值，让相邻差值不再出现 0；也可以在遍历时用 `prediff == 0` 的初始化逻辑处理。

**代码特征**：

```cpp
int result = 1;
int prediff = 0;

for (int i = 0; i < nums.size() - 1; i++) {
    int curdiff = nums[i + 1] - nums[i];
    if ((prediff >= 0 && curdiff < 0) ||
        (prediff <= 0 && curdiff > 0)) {
        result++;
        prediff = curdiff;
    }
}
```

**为什么 `prediff` 初始为 0？**

可以理解为在第一个数前面虚拟了一个和它相同的数，先形成一个平坡。这样第一个真实的上升或下降都会被当作一次有效摆动，结果从 1 开始累加。

### leetcode 53. 最大子数组和

这道题要求选择一个连续的非空子数组，使其中元素的和最大。它可以用 DP，也可以用贪心；两种方法都在判断当前位置应该接在前面的连续子数组后面，还是从当前位置重新开始。

#### 方法一：DP

**核心状态**：

`dp[i]` 表示强制以 `nums[i]` 结尾的最大连续子数组和。因为题目要求子数组连续，所以必须保留结尾位置，不能随意跳过中间元素。

**状态转移**：处理 `nums[i]` 时只有两种选择：接到前面的连续子数组后面，得到 `dp[i - 1] + nums[i]`；或者放弃前面，从 `nums[i]` 重新开始。因此：

```text
dp[i] = max(dp[i - 1] + nums[i], nums[i])
```

**初始化**：`dp[0] = nums[0]`。其余位置可以初始化为 `INT_MIN`，因为数组可能全部是负数，不能把 DP 默认初始化为 0；题目要求子数组必须非空。

**遍历顺序**：从前往后，因为 `dp[i]` 依赖 `dp[i - 1]`。

**为什么要维护 `result`？** `dp[i]` 强制以 `nums[i]` 结尾，但全局最大子数组不一定以最后一个元素结尾，所以每次都要更新：

```text
result = max(result, dp[i])
```

**代码特征**：

```cpp
vector<int> dp(nums.size(), INT_MIN);
dp[0] = nums[0];
int result = dp[0];

for (int i = 1; i < nums.size(); i++) {
    dp[i] = max(dp[i - 1] + nums[i], nums[i]);
    result = max(result, dp[i]);
}
```

因为每次只依赖前一个状态，DP 可以优化为只保留前一个状态，空间复杂度从 `O(n)` 降为 `O(1)`。

#### 方法二：贪心

**贪心策略**：从左到右累加当前连续子数组的和。如果前面的累计和已经小于 0，那么它对后面的任何数字都只会产生负贡献，因此丢弃前面的部分，从当前数字重新开始。

**为什么这样贪心？** 如果当前前缀和 `count < 0`，后面接上任意数字 `x` 都有：

```text
count + x < x
```

所以包含这个负前缀一定不如直接从 `x` 开始。每次累加后都更新 `result`，因此即使之后重置，也不会丢失之前已经出现过的最大值。

**标准流程**：

1. `count += nums[i]`
2. 用 `count` 更新 `result`
3. 如果 `count < 0`，将 `count` 重置为 0，准备从下一个位置重新开始

```cpp
int count = 0;
int result = INT_MIN;

for (int num : nums) {
    count += num;
    result = max(result, count);
    if (count < 0) {
        count = 0;
    }
}
```

**`count == 0` 时到底要不要重置？** 可以重置，也可以不重置，因为和为 0 的前缀不会影响后续结果。但真正必须舍弃的是 `count < 0` 的前缀；不能把 `count == 0` 说成已经产生了负贡献。

**DP 和贪心的关系**：

| | DP | 贪心 |
|---|---|---|
| **状态/变量含义** | `dp[i]`：强制以 `nums[i]` 结尾的最大和 | `count`：当前保留的连续子数组和 |
| **核心决策** | 接上前面，或从当前位置重新开始 | 累计和为负就舍弃前缀 |
| **全局答案** | 遍历时维护 `result` | 每次累加后维护 `result` |
| **空间复杂度** | `O(n)`，可优化为 `O(1)` | `O(1)` |

**易错点**：

1. 不能把 `dp` 或 `result` 初始化为 0，因为数组可能全部是负数，且子数组必须非空。
2. `dp[i]` 不是前 `i` 个数中的最大子数组和，而是必须以 `nums[i]` 结尾的最大子数组和。
3. 不能只看最后一个 `dp[i]`，因为最优子数组可能早就结束了。
4. 贪心重置的关键条件是 `count < 0`；`count == 0` 可以重置，但原因是它对后续没有影响，不是因为它会产生负贡献。

**一句话记忆**：连续子数组 DP 要强制以当前位置结尾；贪心则保留当前累计和，前缀一旦变负就舍弃，并在每一步更新全局最大值。
### leetcode 122. 买卖股票的最佳时机 II

这道题允许多次买卖股票，但必须先卖出后才能再次买入，求能够获得的最大利润。

**你的理解校正**：核心思路完全正确。这里不是把问题变成“比原来简单 1”的数组，而是把任意一段时间内的价格差，拆成每天相邻价格的差值。因为利润具有可加性，所以可以只累加所有正的日差值。

**贪心策略**：

```text
每天利润 = prices[i] - prices[i - 1]
只累加大于 0 的每天利润
```

代码就是：

```cpp
int result = 0;

for (int i = 1; i < prices.size(); i++) {
    result += max(0, prices[i] - prices[i - 1]);
}
```

**为什么可以把一次交易拆开？** 假设连续上涨：

```text
prices[j] - prices[i]
= (prices[i + 1] - prices[i])
+ (prices[i + 2] - prices[i + 1])
+ ...
+ (prices[j] - prices[j - 1])
```

所以从第 `i` 天买入、第 `j` 天卖出的利润，等于这段区间内所有相邻日差值的总和。对于上涨的一段，持有到最后一天和每天分别卖出再买入，利润相同；因此可以直接把每天的正利润全部累加起来。

**为什么负利润不参与？** 如果 `prices[i] - prices[i - 1] < 0`，说明今天比昨天便宜。把这一天的下降也纳入交易，相当于让利润减少；而且既然允许不交易，就可以跳过这段负收益，不会影响后面继续寻找上涨机会。

**为什么初始化 `result = 0`？** 因为可以选择不进行任何交易。当价格一直下降时，所有相邻差值都小于 0，最优策略就是不买不卖，利润为 0；所以 0 就是这种情况下的最大利润。

**局部最优如何推出全局最优**：每天只选择正收益，看起来只是局部选择；但由于一段上涨区间的总利润恰好等于其中所有正日差值之和，所有上涨区间的正收益加起来就是全局最大利润。负收益不会带来额外收益，直接舍弃即可。

**易错点**：

1. 这道题是股票 II，允许多次交易；不能套用只能交易一次的股票题思路。
2. 不能把所有日差值直接相加，下降日的差值必须舍弃。
3. 初始化为 0 是因为“不交易”本身是合法方案，不是因为数组中的价格一定非负。
4. 不需要真的每天卖出再买入；“累加正日差值”只是数学上的等价表达，实际持有一段上涨区间也能得到相同利润。
5. 不能在还持有股票时再次买入；正日差值的累加需要理解为合法交易的等价拆分。

**一句话记忆**：把一次交易的区间利润拆成相邻两天的利润，只收集所有正差值；能涨就赚，下降就不参与，不交易时利润就是 0。
### leetcode 45. 跳跃游戏 II

题目保证最后一个下标可达，要求从下标 `0` 到最后一个下标的最少跳跃次数。

**贪心策略**：把当前一步能到达的所有下标看作一个范围。在这个范围内，检查每个位置下一跳最远能到哪里，取其中能到达的最远边界；扫描完当前范围就必须跳一步，并把这个最远边界作为下一步的范围终点。

直觉上可以说“在当前可达范围里，选下一步潜力最大的点”。更精确地说，算法不必真的把当前位置 `i` 移动到某个具体的“下一跳最远点”；它只需要算出下一步能覆盖的最远边界。

**变量含义**：

- `end`：当前跳数能够到达的最远下标，也就是当前这一层的右边界
- `farthest`：扫描当前范围时，下一跳能够到达的最远下标
- `result`：已经走过的跳跃次数

**遍历流程**：

1. 从左向右扫描当前范围 `[start, end]`。
2. 对每个位置 `i`，用 `i + nums[i]` 更新 `farthest`。
3. 扫描到当前边界 `end` 时，说明当前范围中的候选位置都看过了，必须再跳一步：`result++`，并令 `end = farthest`。
4. 当 `end` 到达或超过最后一个下标时，终点已经被覆盖，不需要再从终点出发跳跃。

**代码特征**：

```cpp
int result = 0;
int end = 0;
int farthest = 0;

for (int i = 0; i < nums.size() - 1; i++) {
    farthest = max(farthest, i + nums[i]);
    if (i == end) {
        result++;
        end = farthest;
    }
}
```

循环只扫描到倒数第二个位置，因为到达最后一个位置就已经完成任务；不需要再从终点多跳一次。题目保证终点可达，因此这里不需要额外处理无法前进的情况。

**为什么这样贪心？** 当前跳数能到达的所有位置，都是下一次跳跃的候选落点。扫描整个范围并取 `farthest`，就得到再跳一步所能覆盖的最远边界。每次都用一步扩展到最远边界，因此在相同跳数下覆盖范围最大，不会比其他选择更差；重复这个过程，最早覆盖终点的层数就是最少跳数。

**与“真的选一个下一跳位置”的区别**：

| 理解方式 | 是否准确 | 原因 |
|---|---|---|
| 选当前范围内 `i + nums[i]` 最大的位置作为实际落点 | 直觉上可帮助理解，但容易误导实现 | 代码无需记录唯一落点，也无需把扫描指针跳到它 |
| 扫描当前范围，维护下一层的最远边界 | 准确的实现描述 | 同一跳数下的候选落点共同决定下一层覆盖范围 |

**易错点**：

1. `i + nums[i]` 表示从位置 `i` 能到达的最远下标；比较它们是在扩展覆盖边界，不是直接把 `i` 更新成这个位置。
2. 只有扫描完当前层的边界 `i == end` 时才增加跳数，不能每看一个位置就 `result++`。
3. 循环通常只到 `nums.size() - 2`，避免到达终点后又多算一次跳跃。

**一句话记忆**：当前范围是一层；扫描这一层内所有位置，找出下一层最远边界，层数就是最少跳数。
### leetcode 1005. K 次取反后最大化的数组和

题目允许恰好进行 `k` 次操作，每次把一个元素取反，要求操作后数组和最大。

**贪心策略**：优先把负数中绝对值最大的（也就是数值最小的）取反成正数，因为这样能让数组和增加最多。负数处理完后，如果还剩操作次数：

- 剩余次数是偶数：对同一个元素反转偶数次，数组和不变。
- 剩余次数是奇数：只需再反转一次绝对值最小的元素，让数组和减少得最少。

**你的理解校正**：每次优先翻转当前最小的数，这个方向正确；负数越小，翻成正数后对总和的提升越大。零的特殊作用也抓到了：`0` 翻转后仍然是 `0`，因此如果有零，可以用它消耗任意剩余操作而不改变总和。更一般地说，负数都翻正后，只需看剩余次数的奇偶性；若奇数且有零，翻转零即可，若没有零，就翻转绝对值最小的数。

**为什么局部最优能推出全局最优？** 对一个负数 `x` 翻转，数组和的变化量是 `-x - x = -2x = 2|x|`。所以应该先翻绝对值最大的负数，才能让和增加最多。所有负数翻正后，再多做一对操作可以在同一个元素上互相抵消；真正影响结果的只剩奇偶性。奇数次无法完全抵消时，选择绝对值最小的元素，损失最小。

**一种实现方式**：按绝对值从大到小排序，依次翻转负数并减少 `k`；如果 `k` 仍为奇数，再把绝对值最小的元素翻转一次。

```cpp
sort(nums.begin(), nums.end(), [](int a, int b) {
    return abs(a) > abs(b);
});

for (int i = 0; i < nums.size() && k > 0; i++) {
    if (nums[i] < 0) {
        nums[i] = -nums[i];
        k--;
    }
}

if (k % 2 == 1) {
    nums.back() = -nums.back();  // 绝对值最小的元素
}
```

**关于“每次重新排序”**：每次取反后重新按数值从小到大排序，也可以实现“每次拿当前最小值”的直觉；更常见的写法是按绝对值降序排一次，先翻较大的负数，最后处理剩余次数的奇偶性。两种写法背后的贪心目标相同。

**易错点**：

1. 应优先翻转绝对值大的负数，而不是绝对值小的负数；因为翻负数 `x` 能增加 `2|x|`。
2. 负数全部翻正后，不必继续逐次模拟；偶数次操作互相抵消，只需判断 `k % 2`。
3. 有零且剩余次数为奇数时，翻转零不会改变总和；若没有零，则翻转绝对值最小的元素。
4. 最后的奇数次处理要找绝对值最小的元素，不一定是数值最小的元素。例如全是正数时，应翻最小的正数。

**一句话记忆**：先把最“值得翻”的负数（绝对值最大）翻成正数；负数用完后，只看剩余次数奇偶，奇数就翻绝对值最小的数，若有零则翻零。
### leetcode 134. 加油站

题目给出 `gas` 和 `cost`，要求找到一个起点，使汽车从该站出发并绕环一周；如果不存在这样的起点，就返回 `-1`。

#### 方法一：暴力枚举起点

你的代码用 `i` 依次尝试每个站作为起点：先把第 `i` 站加油并扣除驶向下一站的油量，记在 `cur` 中；然后用 `index` 沿环形路线继续模拟。`index` 每次通过 `(index + 1) % gas.size()` 前进，回到 `i` 就表示走完一圈。

```cpp
int cur = gas[i] - cost[i];
int index = (i + 1) % gas.size();

while (cur > 0 && index != i) {
    cur += gas[index] - cost[index];
    index = (index + 1) % gas.size();
}
if (cur >= 0 && index == i) {
    return i;
}
```

每个起点最坏要走一圈，因此时间复杂度是 `O(n^2)`，额外空间复杂度是 `O(1)`。

**为什么你的 `while` 用 `cur > 0`？** 这是利用题目“若有解则解唯一”的条件。若某个真正可行的起点在绕回起点之前出现 `cur == 0`，那么从下一站重新出发，后续路线仍可走完；绕回原起点后，原来从起点到该处的净油量又恰好为 0，因此第二个起点也可完成一圈。这会与唯一解矛盾。所以唯一的有效起点在回到自身之前必须保持 `cur > 0`。如果 `cur` 在中途变成 0，这个候选就可以停止尝试；但最终绕回 `i` 时允许 `cur == 0`，因此返回判断仍是 `cur >= 0 && index == i`。

#### 方法二：贪心跳过不可能的起点

贪心版使用你代码里的 `total`、`cur` 和 `start`：

- `cur`：从当前候选起点 `start` 开始，到目前位置为止的净油量。
- `total`：所有站点的净油量总和，用来判断整体是否有解。
- `start`：当前保留的候选起点。

每个站点给 `cur` 和 `total` 都累加 `gas[i] - cost[i]`。如果 `cur < 0`，说明从当前 `start` 出发到 `i` 已经油量不足，因此令 `start = i + 1`，并把 `cur` 清零，从下一个站点重新累计。

```cpp
int total = 0;
int cur = 0;
int start = 0;

for (int i = 0; i < gas.size(); i++) {
    cur += gas[i] - cost[i];
    total += gas[i] - cost[i];

    if (cur < 0) {
        start = i + 1;
        cur = 0;
    }
}
if (total < 0) {
    return -1;
}
return start;
```

**为什么 `cur < 0` 后可以直接从 `i + 1` 开始？** 设当前这段从 `start` 到 `i` 的总净油量为负。此前扫描到的每个前缀都没有小于 0；否则 `start` 早已在那个位置之后重设。对任何中间站 `j`（`start < j <= i`），从 `j` 到 `i` 的净油量等于“`start` 到 `i` 的净油量”减去“`start` 到 `j - 1` 的净油量”。前者小于 0，后者大于等于 0，所以从 `j` 到 `i` 仍然会油量不足。于是 `start` 到 `i` 之间的站都不可能成为起点，可以整段跳过。

**为什么最后检查 `total`？** 如果 `total < 0`，全程油量总供给小于总消耗，无论从哪里出发都不可能完成一圈，所以返回 `-1`。如果 `total >= 0`，贪心留下的 `start` 可完成一圈：从 `start` 到数组末尾，`cur` 没有变成负数；绕回数组开头时，之前的累计前缀相对于 `start` 对应的最低点也不会让油量跌到 0 以下。因此 `total == 0` 也可能有解。

**易错点**：

1. 暴力版利用唯一解保证，在尚未绕回 `i` 时用 `cur > 0` 继续；中途 `cur == 0` 的候选不可能是唯一有效起点。绕回 `i` 后的最终检查仍用 `cur >= 0`，因为最终油量可以恰好为 0。
2. 只有 `cur < 0` 才说明当前候选失败；累计恰好为 0 仍然可行。
3. 贪心中的 `cur` 失败后，排除的是从当前 `start` 到 `i` 的整段起点，而不是只排除 `start` 一个。
4. `total` 和 `cur` 不能混为一谈：`cur` 用于跳过候选起点，`total` 用于判断是否存在解。
5. 总油量刚好等于总消耗（`total == 0`）不代表无解。

**一句话记忆**：暴力法借助唯一解，未回到起点前要求 `cur > 0`，完整绕回时允许 `cur == 0`；贪心法在 `cur < 0` 时把 `start` 更新为 `i + 1`，最后用 `total` 判断有无解。
### leetcode 135. 分发糖果

每个孩子至少分到一颗糖果；如果相邻孩子评分更高，他必须比评分低的邻居多拿一颗。目标是让糖果总数最少。

你这题的核心理解是对的：评分关系有两个方向，单趟从左往右只能自然保证“右边比左边评分高”时的糖果关系；遇到下降段时，需要反向传播，确保左边评分高的孩子也比右边多。

#### 方法一：扫描时遇到下降就用 `j` 向前回溯

你的 `candy` 函数先把 `candy` 全部初始化为 1。外层用 `i` 从左往右扫描：

- 如果 `ratings[i] > ratings[i - 1]`，直接令 `candy[i] = candy[i - 1] + 1`。
- 如果 `ratings[i] < ratings[i - 1]`，用 `j` 从当前位置向前回溯，逐个修正下降链上的糖果数。
- 回溯更新时使用 `max(candy[j] + 1, candy[j - 1])`，因为 `candy[j - 1]` 可能已经由之前的上升关系获得了更大的糖果数，不能被较小的新值覆盖。
- 最后用 `res` 累加 `candy`。

例如评分是 `3, 2, 1`，下降关系需要从右向左传播：先让中间位置比右边多 1，再继续让左边比中间多 1，最终得到 `3, 2, 1`。如果下降前左边已经因上升链拿到更多糖果，`max` 会保留这个更大的值。

**复杂度修正**：这版不是 `O(n)`。虽然外层 `i` 只遍历一次，但内层 `while` 会重复向前访问；评分严格递减时，回溯次数为 `1 + 2 + ... + (n - 1)`，所以最坏时间复杂度是 `O(n^2)`，空间复杂度是 `O(n)`。

#### 方法二：拆成左右两趟扫描

你的 `candy1` 函数把两个方向的约束拆开处理：

1. `candy` 初始化为 1。
2. 第一趟从左往右：若 `ratings[i] > ratings[i - 1]`，设置 `candy[i] = candy[i - 1] + 1`。这一趟只保证右边评分更高时，右边糖果更多。
3. 第二趟从右往左：若 `ratings[i] > ratings[i + 1]`，左边孩子需要比右边多一颗；但不能破坏第一趟已有的约束，因此更新为 `candy[i] = max(candy[i], candy[i + 1] + 1)`。
4. 最后用 `res` 累加所有糖果数。

**为什么第二趟要取 `max`？** `candy[i]` 可能已经因为左边邻居评分更低，在第一趟中被赋予了更大的值。第二趟只需要补足右邻居要求的下界，不能把之前满足的条件覆盖掉，所以取两者最大值。

**为什么两趟后所有相邻关系都满足？** 对任意一对相邻孩子：

- 若左边评分低于右边，第一趟保证右边糖果更多。
- 若左边评分高于右边，第二趟保证左边糖果更多。
- 若评分相同，题目没有大小约束，两人都至少有 1 颗即可。

每一趟都只扫描数组一次，因此时间复杂度 `O(n)`；`candy` 数组占用 `O(n)` 空间。

**易错点**：

1. 只从左往右扫描不能处理所有下降关系；反方向的约束还需要右往左补齐。
2. 第二趟不能直接赋值 `candy[i] = candy[i + 1] + 1`，要和第一趟结果取 `max`。
3. 第一种写法内层 `while` 会在长下降序列中反复回溯，最坏是 `O(n^2)`；两趟分开扫描才保证 `O(n)`。
4. 相邻评分相等时没有“谁必须多拿糖果”的要求，但每个人仍至少拿 1 颗。

**一句话记忆**：左到右处理右边评分更高，右到左处理左边评分更高；第二趟用 `max` 保留第一趟已经满足的糖果数。
